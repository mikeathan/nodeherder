NodeHerder · design exploration

Trust, access, and cleanup

Four screens carry most of the friction: Home cards can look live when they are not, logs are buried in a thin top-level page, alerts vanish after three seconds, and Settings has no maintenance surface. The mocks below show options for each, and the final section repeats every area for a 390 px phone; the report next to this file explains the code evidence and effort.

Recommended kit: 1A + paused banner · 2B/2C logs · 3A/3B alerts · 4B index + 4D cleanup · 5A · mobile M1–M8 No implementation in this pass

1 · Home cards and staleness

highest impact

Today a tile is “online” purely from the Zigbee2MQTT availability flag (deviceStatus), so a device that has gone quiet for hours still renders like a live one. The device’s last_seen already exists but only appears in the Devices list. Three ways to surface age without making every card noisy.

Evidence: EntityTile.vue only prints “Offline” when status === 'offline'; domain/devices/index.ts:66 derives status from availability only. A disconnected browser socket freezes values with no age marker and no per-card signal.

A

Age line on every tile

One extra muted line under the device name; stale cards switch that line to amber and gain a 3 px left edge. Fresh cards stay calm. Most legible; costs one line of tile height.

2 · Console, logs and quick access

information architecture

Console is a top-level nav item with two controls that are really hub settings (remote logging, level), no search, no export, no pause, and a deep watch that scrolls on every message. Meanwhile the backend already lists and serves archived log files (/api/listlogs, /api/logfile) and the frontend never calls them. The recommendation is to treat logs as a utility: a global drawer for “what just happened” plus Settings → Logs & diagnostics for retention, archive download and level.

Evidence: 1,000-message buffer with 24 h expiry in memory only; watch(messages, deep: true); rows keyed by timestamp; no log-file API client; Settings → Logger duplicates the same two controls.

A

Keep a page, but make it a real log viewer

Search, level chips with counts, source filter, problems-only, pause follow, copy, download, and a footer that states buffer and stream state. Good deep-link target and works on a large screen; still one click away from a toast.

useful for deep work

3 · Attention inbox and new-session flag

lost information

Alerts are 3-second toasts with no history. If a toast appears while the user is on another tab, it is gone. Failures, stale devices and connection drops deserve a small inbox with a badge; routine “Saved” confirmations can stay as toasts. On a new session, show one digest rather than replaying a queue of toasts.

Evidence: store/modules/alerts/index.ts uses a fixed TIMEOUT = 3000 and never persists; operationFailed maps straight to alerts/showError. needsAttention() already computes offline/low battery/weak link for Overview but is not global.

A

Header bell → slide-over inbox

Grouped by day, severity icons, deep links and inline actions. Unread count on the bell. “Mark all read” is scoped to the inbox, not the data. Keep toasts only for direct results of a user action (saved, command sent, command failed).

4 · Settings and maintenance

discoverability

Six sections exist today — Appearance, Device defaults, Storage & retention, Logger, MCP server, Assistant, plus the section registry. None are removed in this proposal: the dashboard is an index, and every detail page keeps the same controls it has now, plus the new maintenance actions. The earlier draft dropped MCP and compressed the detail pages; these frames fix that and show the full inventory.

Evidence: Settings.vue + sections.ts define six ids (appearance, device-defaults, storage, logger, mcp, assistant); StorageSettings.vue reads sizes only and its only action is Refresh; MCP has status/Start/Stop/Restart and Assistant has a URL field — both must keep a home. Download helpers already exist for Home (services/home/export.ts) and CSV history.

A

Refined rail: search, summaries, scope badges

Lowest-risk evolution: keep the rail, add a search field, put the current value under each label, and mark rows that are browser-local vs hub-wide. Adds a “Maintenance” group without changing the content layout.

least disruption

6 · Mobile views for every area

390 × 812

Mobile is not a squeezed desktop here. The chosen patterns change shape: tiles go single-column, filter chips scroll, menus become bottom sheets, settings gets a section picker and full-width controls, and destructive actions require a typed confirmation sheet. The header keeps the two shortcuts that matter — notifications and logs.

Touch & reach44 px minimum targets, primary actions in the lower third, no hover-only affordances, no icon smaller than 18 px.
One column, stacked rowsLabel and help above the control; segmented controls fill the width; long values wrap instead of truncating.
Sheets over menusSection pickers, row actions and destructive confirmations open as bottom sheets with a grabber and safe-area padding.
