Spec 035 · catalog by type, entries grouped and searchable

Why this page needs to change with more providers

Today the catalog mixes integration types and providers. Weather needs a special case because four providers would otherwise appear as four unrelated rows.

  • Observed: ConnectionCatalogDialog.vue hard-codes type.id === 'weather' and renders a provider <select>.
  • Observed: catalog already returns types[] and providers[]; the UI does not use that relationship.
  • Observed: the board is an ungrouped grid of widgets; there is no search or status grouping.
  • Consequence: every new capability adds another flat row and another special case.

The rule

  • Type is the unit users think in (“Weather”), provider is an implementation detail (“Open-Meteo”).
  • Providers only appear when choosing or configuring one.
  • Configured entries are grouped by type, searchable, and status-led.
  • No provider-specific branches in generic components.

recommended

Type-first catalog and grouped entries

Integrations ✎ Edit layout＋ Add integration

Catalog

  • Type card shows name, one-line purpose, configured count and worst status.
  • Choosing a type reveals only its providers.
  • Unavailable provider or disk error stays visible, other types still usable.

Entries

  • Grouped by type, one row per configured instance.
  • Status uses dot and words: OK / Stale / Error / Disabled.
  • Subtitle carries provider and location; last refresh is separate.
  • Search matches name, type, provider and location.

Scale

  • Eight entries still scan in two groups.
  • Adding a provider never adds a top-level row.
  • Type sections appear only when at least one entry exists.

detail

Entry detail uses tabs, not a long page

Layout

  • Tabs at ≥768px: Results, Settings, Configuration, Help.
  • Below 768px the same content becomes labelled stacked sections.
  • Refresh and Configure stay in the header on both.

Status

  • Status is server-computed freshness, not a client timer.
  • Error, stale, disabled and offline are distinct words plus icons.
  • Last successful refresh and last check are separate timestamps.

Safety

  • Credentials never appear in Results or Help.
  • Configuration changes still require destination review.
  • Provider text renders as plain text, never markup.
